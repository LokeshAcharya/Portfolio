import socket, threading, logging
from datetime import datetime

# Configure structured logging
logging.basicConfig(
    filename='honeypot.log',
    format='%(asctime)s | %(levelname)s | %(message)s'
)

def handle_connection(conn, addr, port):
    timestamp = datetime.utcnow().isoformat()
    msg = f"[{timestamp}] ALERT: Connection from {addr[0]}:{addr[1]} on port {port}"
    logging.warning(msg)
    alert_engine.trigger(addr[0], port, timestamp)
    conn.close()

def listen_port(port):
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(('', port))
    s.listen(5)
    while True:
        conn, addr = s.accept()
        threading.Thread(target=handle_connection, args=(conn, addr, port)).start()
Lessons Learned
Deploying a real honeypot taught me the value of structured log formats — unstructured logs become useless during incident review. Threading in Python required careful attention to race conditions in shared log state. The GUI/CLI split reinforced the principle of separation of concerns: presentation layer must not block the capture loop.

Detection Rules (MITRE Mapped)
HIGH Brute Force SSH — T1110.001 5+ failed logins in 60s → alert rule_id: 5712
HIGH Exploitation Attempt — T1190 ModSecurity WAF block logged rule_id: 31151
MED OS Command Injection POST body inspection via ModSec rule_id: 932100
LOW Recon Port Scan Detected Nmap SYN scan from VM-3 rule_id: 40101
Key Finding: ModSecurity Gap Fix
Problem: Apache's default logging config omitted POST body content. Attackers sending SQLi/RCE payloads via POST were invisible in standard access logs.
Fix: Deployed ModSecurity with SecRequestBodyAccess On and custom Wazuh decoder to parse ModSec audit log format into structured alerts.
